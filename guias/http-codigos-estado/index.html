Códigos HTTP: qué significa cada respuesta

Entiende la diferencia entre respuestas 2xx, 3xx, 4xx y 5xx y cómo utilizarlas para diagnosticar una página o una API.

La idea principal

Una guía rápida para interpretar códigos HTTP sin memorizar una lista interminable. No necesitas memorizarlo todo de golpe: empieza por el procedimiento básico, prueba un caso sencillo y después utiliza la herramienta para comprobar el resultado.

Las cuatro familias

2xx indica éxito de la petición. 3xx se utiliza para redirecciones y otras respuestas relacionadas con el cambio de ubicación o caché. 4xx suele indicar que existe un problema en la petición del cliente, como 404 o 403. 5xx indica que el servidor no pudo completar una petición válida o encontró un error interno.

404, 403 y 500

Un 404 significa que el recurso solicitado no fue encontrado. Un 403 indica que el servidor entiende la petición pero no permite el acceso. Un 500 es un error interno del servidor y suele requerir revisar registros o la aplicación que genera la respuesta.

Redirecciones

Un 301 o 308 puede indicar que un recurso se ha movido de forma permanente, mientras que 302 y otros códigos de la familia 3xx se utilizan en distintos escenarios de redirección. No conviene elegir un código únicamente porque “funcione”: la intención de la respuesta debe coincidir con el código.

En SEO y desarrollo

Los códigos HTTP ayudan a buscadores, navegadores y herramientas de diagnóstico a interpretar una URL. Para una página eliminada, por ejemplo, no es lo mismo responder con un 404 que redirigirla sin criterio a la portada.

Preguntas frecuentes

¿Un 404 siempre significa que el servidor está caído?

No. El servidor puede funcionar perfectamente y simplemente no encontrar la URL solicitada.

¿Qué significa 401?

Normalmente indica que la petición necesita autenticación.

¿Un 500 es culpa del usuario?

Habitualmente indica un problema en el lado del servidor o de la aplicación, aunque el diagnóstico concreto depende del sistema.
